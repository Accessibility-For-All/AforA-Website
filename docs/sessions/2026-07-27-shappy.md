## Gotchas found
- **Plan Mode toggled mid-session blocks background Agent-tool subagents too, not just the main
  session.** Partway through, the client entered Plan Mode (unclear why — possibly a client-side
  toggle, not something I invoked). Four parallel background agents rewriting the industry pages
  were all still running at that moment; each one silently produced a written plan file instead
  of making edits, without erroring — I only found out when their completion notifications came
  back. After the user exited Plan Mode, I had to explicitly `SendMessage` each stalled agent
  telling it to proceed. **If a background agent's result says "I did research only" or "I wrote
  a plan," check whether Plan Mode was active during its run — it may need to be resumed.**
- **No `gh` CLI in this environment** (confirmed twice, including via PowerShell) — PR creation
  and status checks need a person with GitHub web/CLI access. `git`/`Bash`/`PowerShell` all work
  fine for everything else.
- **No browser-automation tool available either** (no Playwright/Puppeteer MCP connected this
  session) — all visual verification this session was via link-integrity greps, HTML tag-balance
  counts, and a local PowerShell-based static file server (`http://localhost:8080`, see below),
  never an actual rendered screenshot. Recommend a real look at the PR preview before merging.
- **Local static server**: since this is a build-less static site and several pages use
  absolute-path assets (`/favicon/...`), opening files via `file://` breaks those. I started a
  small PowerShell `HttpListener`-based static server on port 8080 (script is in the session's
  scratchpad temp dir, not the repo) rather than assuming Python/Node — neither was installed on
  this machine. It may still be running in the background; safe to stop.
- **VPAT automation split is now a stated fact site-wide**: "~40% completed by automated
  scanning, the remaining 60% requires 3rd-party disability-expert review, per legal stipulation
  and the limits of automation." This replaced a vaguer "automated draft vs. signed version"
  framing. It's now in `pricing.html`'s FAQ and baked into `reports.html`'s illustrative
  percentages — keep any future copy about VPAT/Reports completion consistent with this 40/60
  split rather than reintroducing arbitrary numbers.
- Two of the four industry pages (and `government.html`, fixed directly) had a **pre-existing
  unclosed `<div>` bug** in their "Key Solutions" section markup, invisible in-browser due to
  error-recovery but caught by tag-balance verification. Worth grep-checking div/section counts
  after any future edit to those files.
- `favicon/site.webmanifest` had two pre-existing bugs unrelated to anything requested: icon
  `src` paths were missing the `/favicon/` prefix (so they 404'd), and `name`/`short_name` were
